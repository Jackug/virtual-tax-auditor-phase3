Step 2C — Data Quality & Transformation

Data cleaning and transformation are controlled processes. The original uploaded source is not overwritten.

STEP 1 — ORIGINAL SOURCE
The original uploaded file is retained exactly as received. It remains the source record for auditability.
STEP 2 — PROFILE & VALIDATE
The system checks columns, records, missing values, duplicate structures and other initial quality indicators.
STEP 3 — TRANSFORM
Use the Transform Data workspace to apply controlled operations such as trimming, renaming, filtering, type conversion and duplicate handling.
STEP 4 — PREVIEW
Applied transformations are previewed before a clean version is created.
STEP 5 — CLEAN VERSION
Applying the recipe creates a separate controlled clean data file. The original source is not modified.
STEP 6 — APPROVAL
The clean version is intended to go through controlled human approval before downstream VTA use.

Data Quality Principles

Original Data
Original uploaded files are retained and are not silently overwritten by transformations.
Controlled Transformation
Each transformation is recorded as part of a transformation recipe.
Exceptions
Suspicious or ambiguous records should be flagged rather than silently discarded.
Traceability
The system retains the relationship between the original source and the generated clean version.
Human Control
Cleaning should not become an uncontrolled process that changes the evidence used by the VTA.
Downstream Use
Only data versions that satisfy the required approval controls should become available to downstream VTA engines.
